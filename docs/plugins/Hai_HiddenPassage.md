# Hai_HiddenPassage — 隠し通路（P2）

見た目は壁のまま、**リージョン ID**（マップの層 5）で「通れる・調べると開く・片側からだけ開く・調べると現れる階段」を表す。
タイルセットに「通れる壁タイル」は作らない（[docs/mz-data.md](../mz-data.md) 2.4 の約束）。

## リージョンの表（P2 の帯 250–259）
| リージョン | 意味 | 通れるか（プレイヤー） | 開け方 | 要るイベント |
|---|---|---|---|---|
| 250 | 予約（P2） | — | — | — |
| **251** | 見えない通路（壁に見えるが通れる） | いつでも通れる | 踏むと「発見済み」に入る（演出なし） | なし |
| **252** | 隠し扉（くぼんだ壁） | 見つけるまで通れない | 向かい合って**調べる**（決定キー・タッチ）と開く。文章「隠し扉を見つけた！」と白いフラッシュ | なし |
| **253** | 片側からだけ開く扉 | 表からは通れない。裏から入ると開き、以後は両側から通れる | 裏の側から踏み込む。フラッシュ | 同じ座標に、メモ欄 `<hai_oneway:裏の向き>` のイベント |
| **254** | 隠し階段（ふだんは床） | 床のまま（タイルどおり） | 向かい合うか上に立って**調べる**と現れる。文章「隠し階段を見つけた！」。現れた後に踏むと移動 | 同じ座標に、メモ欄 `<hai_stairs:マップID,x,y>` のイベント |
| 255–259 | 予約（P2） | — | — | — |

- **プレイヤーだけ**に効く。イベント（シンボル敵など）はタイルどおりで、隠し通路を通らない（敵が通路をばらさないため）。仲間の隊列はもともとすり抜ける。
- 開いた・見つけたものは `$gameSystem._hai.hidden` に記録する（セーブに入る）。マップを出入りしても、ロードしても開いたまま。
- 開いた扉の座標には暗いアーチ（Dungeon_B の `B:183`。タイルの通行は×なので、イベントは開いた扉も通らない）を、現れた階段の座標には下り階段（`B:26`）を、第 4 層（z=3）にプラグインが重ねて描く。
  タイルの番号はタイルセットごと・マップごとに変えられる（下の「重ねるタイルをタイルセットごとに変える」）。マップ JSON の z=3 はこの 2 種の座標では空けておく。
- 現れた階段のマスには、描いたタイルの通行に関係なく**4 方向から**入れる（梯子の絵でも横から入れる。プレイヤーだけ。イベントはタイルどおり）。
- その座標にイベントがあれば、開いたときにそのイベントの**セルフスイッチ A を ON** にする（見た目をイベントのページで変えたいとき用。使わなくてよい）。
- マウス・タッチの「目的地へ歩く」の道探しは、まだ見つけていない見えない通路を通らない（クリックで通路がばれないように）。

### メモ欄のタグ
| タグ | 置く所 | 値 |
|---|---|---|
| `<hai_hidden_tiles:D:183,D:26>` | タイルセットかマップのメモ欄 | 開いた扉に重ねるタイル, 現れた階段に重ねるタイル（下の節） |
| `<hai_oneway:up>` | 253 の座標のイベント | **裏がどちら側か**：`up`・`down`・`left`・`right`（`8`・`2`・`4`・`6`、`上`・`下`・`左`・`右` でも可）。`up` なら、上のマスから下へ踏み込むと開く |
| `<hai_stairs:902,23,14>` | 254 の座標のイベント | 行き先の `マップID,x,y`（4 つ目に向き `2/4/6/8` を足してもよい。省略で今の向き） |

イベントはメモ欄を読むためだけのもの：**プライオリティ「通常キャラの下」**（`priorityType: 0`）、画像なし、中身なし（`list` は `code: 0` だけ）にする。
（「通常キャラと同じ」にするとそのマスが通れなくなる。）

### 重ねるタイルをタイルセットごとに変える（P10）
既定の `B:183`（暗いアーチ）・`B:26`（下り階段）は B が `Dungeon_B` のときの絵。B が `Outside_B` のタイルセットでは木箱 C・木製はしごになるので、
タイルセットかマップのメモ欄に `<hai_hidden_tiles:開いた扉,階段>` を書いて変える。

- 値はタイル ID の整数（`695`）か、`B:`〜`E:` と番号（`D:183` ＝ 512 + 183 ＝ 695）。B〜E の範囲（1〜1023）だけ受ける。
- **優先はマップのメモ欄 ＞ タイルセットのメモ欄 ＞ パラメータ（`openDoorTile`・`stairsTile`）**。片方だけ書く（`<hai_hidden_tiles:D:183>`、`<hai_hidden_tiles:,D:26>`）と、書かなかった方は次の段の値。
- 開いた・現れた時と、マップを読み込んだ時（出入り・ロード）に、その時のマップの値で描く。

| タイルセット | B | メモ欄（P10 で追記） | 描かれるもの |
|---|---|---|---|
| 12 V_巡礼の森 | Outside_B | `<hai_hidden_tiles:D:183,D:26>` | D（`Dungeon_B`）の暗いアーチ（695）と下り階段（538） |
| 15 V_魚人の湿地・19 V_異端者の廃集落・20 V_巨人の崖道 | Outside_B | 同上（V2 #58 のマージ後に追記。下の注） | 同上 |
| 11・13・14・16・17・18（B が `Dungeon_B`） | Dungeon_B | なし（パラメータの `B:183`・`B:26`） | 暗いアーチと下り階段 |

外のタイルセットは D を必ず `Dungeon_B` にそろえてある（[docs/look.md](../look.md) 2.4）ので、どれも同じ値。B が `Outside_B` で D が `Dungeon_B` でない
タイルセットを作るときは、そのタイルセットの絵に合わせてメモ欄を書く。見本とテストは `tools/maps/src/p10_hidden_tiles.txt`・`.json`（→ `data/Map911.json`、タイルセット 12）。

## 手がかりの描き分けの規則（描画の仕上げは V1、規則は P2）
隠し通路には**必ず**手がかりを 1 つ以上付ける（VISION.md 核 1）。

| 手がかり | 付ける所 | 描き方（タイル） | 文字マップの文字（`dungeon`） |
|---|---|---|---|
| 一マスだけ植生（模様）が違う床 | 見えない通路の入口の**手前の床** 1 マス／隠し階段のマス | 第 2 層（z=1）に重ねる A2 のオートタイル（苔 `A2:23`、ひび割れ `A2:7`）。1 マスだけなので孤立の形になる | `%`（苔の床）、`v`（ひび割れの床＝隠し階段） |
| 影の無い壁 | 見えない通路の壁 | 通路の壁は**右のマスに影（z=4）を落とさない**。通路の出口側の部屋で、壁ぎわの影が 1 マスだけ途切れて見える | `H`（`shadow: false`） |
| くぼんだ壁 | 隠し扉 | 周りの壁と**別の A4 の kind** の側面（岩の壁 `A4:9` に対して、段差の岩 `A4:45`）。kind が違うので縁が出て、くぼんで見える | `D` |
| 逆側から来て初めて開く扉 | 片側扉 | 表から見ると周りと同じ壁（手がかりは「裏から来ると開く」こと自体）。開くと暗いアーチになる | `O` |

- 別のタイルセット（W レーンが使うもの）でも同じ考え方で文字を足す：苔・ひび割れは z=1 の A2、影なしは `shadow: false`、くぼみは別の A4 の kind。
- 手がかりの見た目を変える（V1）ときも、**リージョンとタグの意味は変えない**。

## W レーンが隠し通路を置く手順（文字マップ）
凡例 `dungeon`（`tools/maps/legend.json`）に入っている文字：

| 文字 | 中身 | リージョン |
|---|---|---|
| `%` | 苔の床（手がかり。見えない通路の手前に置く） | 0 |
| `H` | 見えない通路（岩の壁に見えて通れる。右に影を落とさない） | 251 |
| `D` | 隠し扉（くぼんだ岩の壁） | 252 |
| `O` | 片側扉（岩の壁と同じ見た目） | 253 |
| `v` | 隠し階段（ひび割れの床） | 254 |

1. 2 つの部屋の間の壁に `H` を並べ、片方の部屋の入口の手前の床を `%` にする。
2. 隠し扉は、部屋の上の壁の**一番下の段**（床のすぐ上の側面）に `D` を置き、その奥を `H` でつなぐ。
3. 片側扉は `O` を置き、同じ座標にイベントを置く（裏の向きをメモ欄に書く）。奥は `H` でつなぐ。
4. 隠し階段は床に `v` を置き、同じ座標にイベントを置く（行き先をメモ欄に書く）。
5. 隠し部屋のご褒美（赤い宝箱 `!Chest` の 0 番）を置く。

設定（`tools/maps/src/<名前>.json`）のイベントの書き方：
```json
{ "at": "O", "name": "片側扉", "type": "raw", "note": "<hai_oneway:up>", "pages": [{ "priorityType": 0 }] },
{ "at": "v", "name": "隠し階段", "type": "raw", "note": "<hai_stairs:902,23,14>", "pages": [{ "priorityType": 0 }] }
```
同じ文字が地図に何か所もあるときは `"at"` の代わりに `"x"`・`"y"` で 1 つずつ置く。

見本は `tools/maps/src/p2_hidden.txt`・`.json`（→ `data/Map902.json`）。

## 窓口（`window.Hai.HiddenPassage`）
| 関数 | 中身 |
|---|---|
| `found(mapId?)` | 見つけたものの一覧 `[{ mapId, x, y, region }]`（mapId を渡すとそのマップだけ）。U1 のオートマップが読む |
| `isFound(x, y, mapId?)` | その座標を見つけたか |
| `isHiddenAt(x, y)` | 今のマップのその座標が隠し通路（251–254）で、**まだ見つけていない**か |
| `regionKind(x, y)` | 今のマップのその座標の隠し通路の種類（251–254。違えば 0） |
| `overlayTiles()` | 今のマップで開いた扉・現れた階段に重ねるタイル `{ door, stairs }`（マップ ＞ タイルセット ＞ パラメータ） |
| `revealAt(x, y, mapId?, region?)` | 見つけたことにする（演出なし）。新しく見つけたら true。ほかのマップの座標なら `region`（251–254）も渡す |
| `REGION` | `{ PASSAGE: 251, DOOR: 252, ONEWAY: 253, STAIRS: 254 }` |

状態：`$gameSystem._hai.hidden = { found: { "902,16,8": 252, … } }`（キーは `マップID,x,y`、値はリージョン）。
