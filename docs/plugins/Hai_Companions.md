# Hai_Companions — 仲間：遺骸と形見・名の壁・控え・記憶の断片（P6・P11）

VISION.md の核 5「仲間は死者の霊。遺骸を見つけ、拠点で呼び戻す。記憶 4 断片で完全体」のためのプラグイン（#45、7 人にしたのは #134）。
仲間 7 人の設定は [docs/world.md](../world.md) 6 章（6.2 一覧・6.3 遺骸と形見の置き場所・6.4 記憶 4 断片・6.6 目覚めの一言）。
仲間は旅の途中で出会う**見知らぬ死者**。墓守とは縁がなく、初対面として話す。主人公を名前でも「墓守」でも呼ばない（6.1）。
**本文（遺骸・形見・記憶の文章）はイベントの「文章の表示」（101・401）に書く。プラグインは本文を持たない**（W レーンが 6 章の表をそのまま写せるように）。
プラグインが持つのは「見つけた・呼んだ・読んだ」の状態と、本文の後ろに足す一行・名の壁の輪・編成の画面。

墓守（主人公）の記憶は仲間ではなく、**会話できない薄い思念**にある。そちらは [Hai_Thoughts](Hai_Thoughts.md) の `<hai_faint>`。

### 遺骸・形見のふるまい
- 調べると、イベントの文章がそのまま出て、その後に効果音（Teleport）と「**名の壁の輪に置けば、この人を呼べる。**」（名前は出さない。名前は目覚めたときに分かる）。
- 読み終えたら（イベントの処理が終わったら）：見つけた扱い（`found[5] = true`）、そのイベントの**セルフスイッチ A を ON**、スイッチ 131〜137 を ON（下の「筋の旗」）。
- 2 ページ目（セルフスイッチ A）を画像なし・中身なしにすると、遺骸が消える（持ち帰った）。
- 見つけたあとに同じ遺骸を調べても、一行は足さない。
- 形見を取り引きで受け取る形（ベルトランの骨の剣を骨拾いから返してもらう。6.3）は、取り引きが済んだら `<hai_remains:10>` の形見のイベントが出るようにする（出現条件を取り引きのイベントのセルフスイッチか W のスイッチにする）。

### 記憶の断片のふるまい
- 調べると、イベントの文章の後に「**メモ：ブルーノの記憶 2/4「転機」**」（効果音 Book1）。
- 読み終えたら：`memories[5][2] = true`、セルフスイッチ A を ON、メモ帳に一行（`Hai.Thoughts.addNote`、kind `"memory"`、ID `memory:5,2`）、変数 131〜137 に読んだ数。
- **4 つ目**を読むと、続けて完全体の知らせ（`completeMessage`。効果音 Saint5）。
  その仲間が `<hai_complete:5>` のスキルを覚える。**仲間がまだ加わっていなくても**読めて、覚えた技は呼んだときに持っている。
  - 知らせは**その仲間を連れているときだけ**出す（P20 #292。R3 気になる 5）。まだ呼んでいない（パーティにいない）仲間の 4 つ目では出さず、
    名の壁で呼んだとき、目覚めの文のあとに一度だけ出す（`$gameSystem._hai.companions.told[ID]` に出したことを覚える）。
  - 「完全体」は仕組みの言葉なので、知らせの文には入れない。P20 で `@default` を「ブルーノの記憶が、四つとも戻った。／ブルーノは「行軍」を思い出した。」にした。
    `js/plugins.js` の値（今は前の文「…は完全体になった！／強技「…」を覚えた。」）を同じ文に替えるのは持ち主（owner-fixes.md 持-9）。
- 読み直しても一行も知らせも出ない。`<hai_thought>` と同じイベントに書いてもよい（「（読んだ）」は Hai_Thoughts が付ける）。
- 遺骸と記憶を 1 つのイベントにまとめてもよい（`<hai_remains:5><hai_memory:5,4>`。ブルーノの臨終は遺骸と同じ 021 礼拝堂）。足す行は「この人を呼べる」→「メモ」→「完全体」の順。
- 記憶の中身は**その人の人生と無念だけ**（6.4）。主人公の正体を指さす言葉は入れない。

## プラグインコマンド
| コマンド | 引数 | 中身 |
|---|---|---|
| `summonMenu`（名の壁で呼ぶ） | なし | 見つけた遺骸・形見のうち、まだ呼んでおらず、パーティにいない仲間を選択肢で出す（最後に「やめる」）。選ぶと 効果音 → 暗転 → 呼ぶ → 明るくなる → 「〜が目を開けた。」→ 目覚めの一言。誰もいなければ「輪は暗いままだ。呼べる人の遺骸も形見も、まだ置いていない。」 |
| `partyMenu`（編成） | なし | 編成の画面を開く（下） |
| `summon` | `actorId` | 演出なしで呼ぶ（見つけた扱いにもする） |

### 編成の画面（`Scene_HaiParty`）
- `Window_MenuStatus`（メニューの「並び替え」と同じ窓）にパーティ全員。1 人選び、もう 1 人選ぶと入れ替わる。同じ人をもう一度選ぶか、キャンセルで取り消し。
- **上から 4 人が戦闘に出る**（`maxBattleMembers`）。控え（5 人目から）は顔が薄く出る（MZ の既定）。7 人そろうとパーティは 8 人。
- **主人公（アクター 1）は控えに回せない**：入れ替えると主人公が 5 番目以降になるときはブザーが鳴り、上の説明が「〜は控えに回せない。」になる。
  これは `Game_Party.swapOrder` で守っているので、メニューの「並び替え」でも同じ（そちらは何も起きないだけ）。

### 行軍（`<hai_vow>`）
MZ の「かばう」は HP が 1/4 を切った味方しか守らないので、`<hai_vow>` のステートの者がいる間は、味方への**物理**攻撃（必中でないもの）を必ず身代わりで受ける
（`BattleManager.checkSubstitute`・`Game_Unit.substituteBattler` の alias）。反撃はステートの「反撃率 100%」。

### 檻破り（`<hai_user_state>`）
スキルの効果は対象にしか付かないので、「使った者に付けるステート」をメモ欄で決める（`Game_Battler.useItem` の alias）。トゥーラの「檻破り」は
戦闘不能の味方 1 人を起こし（効果）、使ったトゥーラにステート 193「檻破り」（2 ターン、狙われ率 1000%・物理ダメージ率 70%）を付ける。

## 筋の旗（スイッチ 131–150・変数 102・131–138。P11 の帯。W の帯の中の例外）
状態は `$gameSystem._hai.companions` が正本。W のイベントが条件分岐・出現条件で見られるように、変わったときにスイッチと変数へ**写す**（パラメータで番号を変えられる。0 で写さない）。
仲間の並び（パラメータ `companionActors`、既定 `5,6,7,8,9,10,11`）の順に 1 つずつ後ろ。

| 旗 | 既定 | いつ |
|---|---|---|
| 遺骸:ブルーノ〜トゥーラ | スイッチ 131〜137 | 遺骸か形見を見つけたとき |
| 加入:ブルーノ〜トゥーラ | スイッチ 138〜144 | 名の壁で呼んだとき |
| （空き） | スイッチ 145〜150 | 使っていない |
| 仲間の数 | 変数 102 | 呼んだとき（呼んだ人数 0〜7） |
| 記憶:ブルーノ〜トゥーラ | 変数 131〜137 | 記憶を読んだとき（読んだ数 0〜4）。**4 なら完全体** |
| 戻った記憶の数 | 変数 138 | 薄い思念を見たとき（`Hai_Thoughts` が写す） |

- **完全体のスイッチは使わない**（`completeSwitchStart` の既定は 0）。7 人 × 3 種類のスイッチは帯（20 個）に入らないため。完全体はイベントの出現条件「変数 131〜137 ≧ 4」で見る。
- `System.json` に名前の無い番号は、コアが書き込みを無視する（`p6_data.mjs` が名前を入れる）。旗はイベントの側から変えない（プラグインの状態とずれる）。

## 名前の欄（docs/world.md 3.1）
主人公の名前の欄は最初「墓守」。最後の地域で相棒の司祭の薄い思念が名前を返したら、イベントの**名前の変更（320）**で「ルカ」にする（仕組みは足さない）。
```json
{ "code": 320, "indent": 0, "parameters": [1, "ルカ"] }
```
- 名前の欄の初期値「墓守」は `Actors.json` の 1 番（持ち主の帯）。持ち主がエディタで入れる。
- 「ルカ」にしたあとは、使ってよいマップ（world.md 10 章）のほかで `\N[1]` を使わない。編成の断りの文「%1は控えに回せない。」は主人公の今の名前を出す。

## W レーンが遺骸と記憶を置く手順（文字マップ）
設定（`tools/maps/src/<名前>.json`）の `events` に書く。見本は `tools/maps/src/p6_companions.txt`・`.json`（→ `data/Map907.json`）。

### 遺骸・形見（docs/world.md 6.3）
1. 場所のマスに文字を置き（`chars` に `{ "as": "." }` で足す）、`type: "raw"` で 2 ページ。
2. 1 ページ目：遺骸の絵（`Damage1` などの倒れた人。形見は `!Weapon` など）・「通常キャラと同じ」・決定ボタン、list に遺骸の文章（101・401）。2 ページ目：セルフスイッチ A、画像なし、中身なし。
3. `note` に `<hai_remains:アクター ID>`。名前に「遺骸」を入れる（T2 の到達性の検査が「遺骸」を見る）。

```json
{
  "at": "a", "name": "遺骸 ブルーノ", "type": "raw", "note": "<hai_remains:5>",
  "pages": [
    { "image": { "characterName": "Damage1", "characterIndex": 0, "direction": 2, "pattern": 1 }, "priorityType": 1, "trigger": 0,
      "list": [
        { "code": 101, "indent": 0, "parameters": ["", 0, 0, 2, ""] },
        { "code": 401, "indent": 0, "parameters": ["礼拝堂の方を向いて、鎧の大男が座っている。"] },
        { "code": 401, "indent": 0, "parameters": ["手の甲の鐘だけが、布で巻かれていない。"] },
        { "code": 0, "indent": 0, "parameters": [] }
      ] },
    { "conditions": { "selfSwitchCh": "A", "selfSwitchValid": true }, "priorityType": 0 }
  ]
}
```

### 記憶の断片（docs/world.md 6.4）
1. 場所のマスに文字を置き、`type: "text"` のイベントにする（読み直せるように 1 ページのまま）。
2. `note` に `<hai_memory:アクター ID,番号>`（番号は 1 生い立ち・2 転機・3 罪か誇り・4 臨終）。残留思念としても数えるなら `<hai_thought:ID>` も書く。
3. `lines` に本文を写す（1 ページ 4 行まで。多ければ配列の配列）。地の文の一人称は 11 章の口調の表（ブルーノは「僕」）。
4. 臨終は遺骸と同じ所のことが多い：遺骸のイベントの `note` を `<hai_remains:5><hai_memory:5,4>` にし、本文を 6.4 の臨終にする。

### 名の壁の輪（Map010 の名の壁。W が作り直す 010 に置く）
list を「プラグインコマンド Hai_Companions → 名の壁で呼ぶ」だけにする。名の壁の説明はしない（誰も理由を説明しない。6.1）。
```json
{ "code": 357, "indent": 0, "parameters": ["Hai_Companions", "summonMenu", "名の壁で呼ぶ", {}] }
```
編成は同じく `partyMenu`（輪を調べたときの選択肢にするか、別の置物にするかは W が決める）。
