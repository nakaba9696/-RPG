# データの道具と検査（tools/data/）

| ファイル | 中身 |
|---|---|
| `io.mjs` | `data/*.json` を読む・書く（エディタと同じ書式）・空の項目で伸ばす（T1・T3） |
| `check.mjs` | 整合の検査。`checkAll()` が問題の一覧（文字列の配列）を返す。空なら合格 |
| `reach.mjs` | マップの到達性（プレイヤーが歩いて行けるマス）の計算（T2） |
| `bands.json` | ID の帯（`docs/ROADMAP.md` の「ID の帯」と「割り当て表」の写し。T2） |

```bash
node tools/data/check.mjs     # 単独で走らせる（問題があれば一覧を出して終了コード 1）
node tests/t_data.mjs         # 同じ検査 ＋ 書式（tests/run.mjs からも走る）
node tests/t_reach.mjs        # 到達性などの検査が、わざと壊したデータで落ちることの確かめ
```

## 検査の一覧
問題の文は「どのファイルの、どの座標の、どのイベントが、どうなっているか」の形で出る。

| 検査 | 見ること | 出る文の例 |
|---|---|---|
| 表の形（T1） | 0 番目が `null`、`id` が添字と同じ、空（`null`）の項目が無い | `Items.json[5]: id が 6（添字と同じであること）` |
| イベントの命令（T1） | `list` が `code: 0`・`indent: 0` で終わる、`indent` が飛ばない | `data/Map902.json events[4]「赤い宝箱」 pages[0]: list が …で終わっていない` |
| マップの対応（T1） | `MapInfos.json` と `MapNNN.json` が 1 対 1、`data` の長さ、`tilesetId`、イベントが地図の中 | `data/Map905.json: MapInfos.json に 905 番の要素がない` |
| `js/plugins.js`（T1） | プラグインのファイルが在る、2 回ない、パラメータが文字列 | `js/plugins.js: js/plugins/Hai_X.js がない` |
| **場所移動の行き先**（T2） | イベントの場所移動（201、直接指定）・隠し階段 `<hai_stairs:map,x,y>`・`Hai_Defeat` の「拠点を設定」・`System.json` の開始位置が、在るマップの、地図の中の、**通れるマス**（壁のタイル（A3・A4）でなく、通せんぼのイベントが無く、1 歩でも動ける）。製品のマップからテスト用のマップ（900–949）へ行かない | `data/Map902.json (25,14)「上り階段」: 場所移動の行き先（マップ 902 の (0,0)）が壁か、どこへも動けないマス` |
| **届くか**（T2） | 宝箱（画像 `!Chest` か 名前に「宝箱」）・遺骸（名前に「遺骸」）・残留思念（`<hai_thought>` か 名前に「残留思念」）・施錠扉（`<hai_locked>`）・シンボル敵（`<hai_enemy>`）・場所移動（201）のイベントに、入口から歩いて届く。施錠扉は、鍵（`<hai_key:アイテムID>`）をくれるイベントに届けば開き、奥も数える | `data/Map902.json (17,4)「赤い宝箱」: 宝箱に入口 (23,14)・(4,10)・(5,11) から届かない（隠し通路 251–254 込み）` |
| 施錠扉の鍵（T2） | `<hai_locked>` の扉に `<hai_key:…>` があり、その鍵が手に入る | `… 施錠扉の鍵 Items 999 が手に入らない（鍵をくれるイベント（126）が無いか、届かない）` |
| 入口（T2） | どのマップにも入口がある（持ち主の 1–9 は見ない） | `data/Map909.json: 入口がない（…）。文字マップに S（テストの開始地点）を置く` |
| **リージョン**（T2） | 251・252・253 のマスは見た目が壁（タイルの通行が × か、A3・A4 の壁）。254（隠し階段）は床。253 には `<hai_oneway>`、254 には `<hai_stairs>` のイベントが同じ座標にある | `data/Map900.json (6,7) リージョン 251: 隠し通路が通れるタイルの上にある（見た目が壁のタイルに置く）` |
| **ID の帯**（T2） | 名前の接頭辞（`T_`・`P1_`・`W1_` など）から帯を引き、その帯に収まる。接頭辞の無いものは、どれかのレーンの帯に入っている | `Troops.json[121]「P1_はみ出し」: 121 番は P1 の帯（101–120）の外` |
| **プラグインの並び**（T2） | `Hai_TestHooks` → `Hai_SymbolEnemy` → `Hai_HiddenPassage` → `Hai_MapTone` → `Hai_Battle` → `Hai_Thoughts` → `Hai_Defeat`（在るものだけ） | `js/plugins.js: 並びが違う。今は …、正しくは …` |

## 到達性の決まり（`reach.mjs`）
通行の規則はコアスクリプト（`js/rmmz_objects.js`）と `js/plugins/Hai_HiddenPassage.js` を読んで同じにしている。
- **タイル**：`Game_Map.checkPassage` と同じ。タイルイベント（画像がタイルで「通常キャラの下」）→ 層 3・2・1・0 の順に、☆（`0x10`）でない最初のタイルの 4 方向のビットで決まる。
  1 歩は「今のマスから出られる」かつ「行き先に逆向きから入れる」（`Game_CharacterBase.isMapPassable`）。
- **イベント**：「通常キャラと同じ」（`priorityType: 1`）で すり抜けでないイベントは壁。ページは**ニューゲームの直後に出るページ**で見る。
  - どこかのページで通れるイベント（スイッチで開く扉など）は通れる扱い（仕掛けは静的には解けないので、落としすぎない側に倒す）。
  - シンボル敵（`<hai_enemy>`）と、自律移動が「固定」でないイベントは動くので壁にしない。
  - `<hai_locked>` の扉は、鍵をくれるイベント（アイテムの増減 126 で `<hai_key>` のアイテムを増やす）に届くまで壁。届いたら開き、ほかのマップの鍵でもよい。コモンイベントがくれる鍵は最初から持っているとみなす。
- **隠し通路**（`Hai_HiddenPassage`、プレイヤーだけ）：
  - 251 見えない通路はいつでも入れる。252 隠し扉は「調べれば開く」ので入れる扱い。
  - 253 片側扉は `<hai_oneway>` の**裏の側から**踏み込んだときだけ入れる（プラグインと同じ。いったん入れば開くので、それで足りる）。
  - 251〜253 のマスからは、タイルに関係なく出られる。ただし出た先が壁（A3・A4）なら出られない。
  - 254 隠し階段はふだんの床。行き先（`<hai_stairs>`）は場所移動として入口に数える。
- **届く**：イベントのマスに立てるか、上下左右のどれかのマスに立てれば届く（向き合って決定キーで調べられる。`Game_Player.checkEventTriggerThere` は前のマスの通行を見ない）。
- **入口**：`System.json` の開始位置、すべての場所移動（201・`<hai_stairs>`・`Hai_Defeat` の拠点）の行き先。
  テスト用のマップ（900–949）は、文字マップ（`tools/maps/src/*.txt`）の **`S`**（設定の `chars` に `S` があるもの。テストの開始地点）も入口にする。
  場所移動の元のイベントに届くかは問わない（マップごとに見る）。

## 落ちたときの直し方（W レーン向け）
| 出た文 | 直し方 |
|---|---|
| 〜に入口 … から届かない | 文字マップで、入口からそのイベントまで床がつながっているかを見る。隠し部屋なら、壁に `H`（251）を並べる・`D`（252）を置く。片側扉 `O`（253）は `<hai_oneway>` の向きが**裏の側**（来る側）になっているか。施錠扉の奥なら、鍵の宝箱（126 で `<hai_key>` のアイテムを増やす）が扉の手前から届く所にあるか |
| 施錠扉の鍵 Items N が手に入らない | 鍵をくれるイベント（126）を置く。`<hai_key:N>` の番号と、くれるアイテムの番号を合わせる。鍵を扉の奥に置いていないか |
| 場所移動の行き先が壁か、どこへも動けないマス | 行き先の x・y を、行き先のマップの床のマスに直す（文字マップの行が y、列が x。0 始まり）。行き先のマスにイベントを置かない |
| 場所移動の行き先のマップがない／地図の外 | マップ ID と座標の打ち間違い。行き先のマップを先に作る |
| 入口がない | そのマップへ来る場所移動を、どこかのマップに置く（テスト用のマップなら文字マップに `S` を置き、設定の `chars` に `S` を足す） |
| 隠し通路が通れるタイルの上にある | 251〜253 は壁の文字（`H`・`D`・`O`）に置く。床の上に置くと隠れていない |
| 隠し階段は床のタイルに置く | 254（`v`）は床に置く |
| 〜番は 〜の帯（…）の外 | 自分の帯の番号に移す（`docs/ROADMAP.md` の「割り当て表」）。帯が足りなければ PR の説明に書いて配り役に頼む |
| 接頭辞 〜 が割り当て表に無い | 配り役が割り当て表に足すのを待つか、名前の接頭辞を直す。割り当て表に足したら `tools/data/bands.json` の `issues` にも足す |
| 製品のマップからテスト用のマップへ行ける | 900–949 への場所移動を製品のマップから消す |
| プラグインの並びが違う | `js/plugins.js` の行を上の順に並べ直す |

## `bands.json` を直すとき
`docs/ROADMAP.md` の「ID の帯」か「割り当て表」を変えたら、**同じ PR で `bands.json` も直す**（二重に持っているため）。
- `lanes`：レーンごとの帯（`owner` は持ち主）。`issues`：割り当て表の 1 行ずつ。ROADMAP の「—」は `[]`。
- 種類：`switches`（スイッチ・変数）、`maps`、`database`（Skills・Items・Weapons・Armors・Enemies・Troops・States・Animations）、
  `commonEvents`、`actors`（Actors・Classes）、`tilesets`。issue に種類が無ければレーンの帯で見る。
- `testMaps`：テスト用のマップの帯（製品から行けない。入口に文字マップの `S` を使う）。
